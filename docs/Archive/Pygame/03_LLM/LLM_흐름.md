# LLM 흐름

> 사용자의 발화가 LLM을 거쳐 데이터 변경/응답으로 이어지는 전체 파이프라인.

관련 문서: [[Archive/Pygame/03_LLM/시스템_프롬프트]], [[Archive/Pygame/03_LLM/Skill_개요]], [[Web/01_페이지/공통_AI대화창]], [[Web/05_백엔드/AI_연동]]

---

## 전체 파이프라인

```
사용자 발화
   ↓
[1] 컨텍스트 수집 (현재 화면, 선택된 객체, 통계, 최근 대화)
   ↓
[2] 시스템 프롬프트 + 컨텍스트 + Skill 카탈로그 + 발화를 LLM에 전송
   ↓
[3] LLM이 응답을 생성
     - 일반 텍스트 응답
     - 또는 Skill 호출(JSON 도구 사용 형식)
   ↓
[4] Skill 호출이 있으면:
     - 확인이 필요한 동작은 사용자에게 되묻고
     - 동의 시 SkillRegistry가 해당 Skill 실행
     - 결과를 다시 LLM에게 전달해 자연어 응답 합성
   ↓
[5] 응답 표시 + 대화 로그 기록
```

## 3. LLM 응답 종류

LLM은 다음 중 하나로 응답한다.

- **단순 텍스트**: 추가 정보 요청, 잡담, 회고 질문.
- **Skill 호출**: 정해진 Skill 이름과 인자 JSON.
- **둘 다**: "이 식물에 새 꽃을 피울까요?" 같은 확인 텍스트와 함께 후속 Skill 의도가 표시될 수 있다(실행은 사용자 동의 후).

---

## 4. Skill 실행

- [[클래스_함수_사전#SkillRegistry]]가 이름으로 dispatch.
- 각 Skill은 자체 검증(존재하지 않는 봉우리/식물 등)을 수행.
- 결과는 표준 형식의 JSON으로 반환:
  - `ok`: bool
  - `message`: str (사용자에게 보일 짧은 문장 또는 LLM이 합성할 재료)
  - `data`: 객체 (선택적)
- 실패 시 LLM에 오류 사유를 돌려주고 LLM이 사용자에게 다시 묻는다.

---

## 5. 응답 표시 / 로그

- 최종 응답이 [[Web/01_페이지/공통_AI대화창]]에 표시.
- 메시지와 Skill 호출 기록은 [[ConversationLog_JSON]]에 추가.

---

## 의도 분류

LLM에게 명시적인 의도 분류기를 따로 두지 않는다. 시스템 프롬프트에 Skill 카탈로그가 충분히 자세히 들어 있어 LLM이 적절한 Skill을 직접 선택하도록 한다. 모호하면 LLM이 사용자에게 되묻도록 프롬프트에 지시.

---

## 확인이 필요한 동작

- 새 식물 생성([[create_plant]])
- 봉우리 포기([[abandon_bud]])
- 식물 삭제([[delete_plant]])
- 마감일 변경([[set_deadline]])

이 동작들은 LLM이 곧장 실행하지 않고 사용자 확인 발화를 받은 뒤 호출한다. 자세히는 [[Web/01_페이지/공통_AI대화창#확인이-필요한-동작]].
