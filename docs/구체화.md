# Plant Counselor 기능 구체화

> 나의 계획, 고민, 일정 등을 식물로 시각화하는 LLM 기반 웹 서비스.
>
> 최종 점검: 2026-06-05
>
> 제품 메타포, UX 의도, Figma/프론트 동기화 규칙을 모은 문서다. 구현 세부는 실제
> 코드와 루트 `AGENTS.md`를 우선한다.

---

## 1. 핵심 개념(메타포)

프로그램의 모든 데이터는 다음의 식물 메타포로 표현된다.

| 식물 요소           | 의미             | 사용자 경험상의 의미                |
| --------------- | -------------- | -------------------------- |
| **정원(Garden)**  | 사용자 1명의 전체 공간  | 로그인한 사용자의 홈                |
| **식물(Plant)**   | 하나의 "분야(카테고리)" | 학업, 돈, 연애, 건강, 취미 등        |
| **봉우리(Bud)**    | 분야 안의 개별 고민/일정 | "기말 프로젝트 마무리", "어머니 생신 준비" |
| **꽃(Flower)**   | 진행 중인 상태       | 작업이 활발히 진행되는 단계            |
| **열매(Fruit)**   | 마무리 직전 단계      | 결과가 가시화된 단계                |
| **수확(Harvest)** | 완료             | 고민 해결 / 일정 완료              |
| **시듦(Wilting)** | 정체 상태          | 오랫동안 진행되지 않음               |
| **썩음(Rot)**     | 포기됨            | 사용자가 포기 선언한 봉우리            |

봉우리의 생애주기:
**봉우리(Bud) → 꽃(Flower) → 열매(Fruit) → 수확(Harvest)**
중간에 정체되면 → **시듦(Wilting)**, 포기하면 → **썩음(Rot) → 사라짐**

## 2. 시스템 구조 개요

### 2.1 사용자 단위
- Supabase Auth Google OAuth 기반으로 로그인한다.
- 사용자 데이터는 Supabase PostgreSQL에 저장하고, 백엔드는 `supabase-py` PostgREST HTTP
  클라이언트로 접근한다.
- 사용자별 데이터 격리는 repository 쿼리의 `user_id` 필터와 백엔드 인증 의존성으로
  강제한다.
- LLM 호출은 Google Gemini를 사용하며, 서버 환경변수 `LLM_API_KEY`를 사용한다.

### 2.2 데이터 단위(논리적 구조)
- **User**: 로그인 정보, 프로필, 환경설정.
- **Garden State**: 현재 진행 중인 식물/봉우리 통계 캐시, 마지막 접속 시각.
- **Plant**: 분야 단위 식물. 이름, 종(species, 시각적 외형), 생성일, 분야 설명, 색감.
- **Bud**: 고민/일정 단위. 상태(bud/flower/fruit/harvested/wilting/rot), 생성일, 마지막 진행일, 마감일(optional), 진행률, 메모, 대화 로그 ref.
- **Conversation Log**: AI와의 대화 기록(봉우리/식물에 묶임).

### 2.3 LLM의 역할
LLM은 UI의 "버튼"을 대체한다. 사용자는 채팅으로 거의 모든 동작을 수행한다.
- 새로운 고민/일정 발화 → 분류 → 식물 매칭 또는 신규 식물 제안
- 진행 상황 발화 → 봉우리 상태 업데이트(꽃/열매 등)
- 포기/완료 발화 → 봉우리 상태 전이
- 통계/회고 질문 → 정원 데이터 기반 응답
- 매일/주기적으로 시들어가는 봉우리에 대한 알림 생성

## 3. 페이지 구성

프로그램은 크게 **홈 / 식물 / 설정** 3개의 메인 화면을 가진다. 공통 영역으로 **AI 대화창**이 항상 호출 가능해야 한다.

### 3.1 홈(Home)

홈은 "정원의 한눈 보기" 페이지이다.

**3.1.1 상단 요약 카드**
- 진행 중인 고민 수
- 진행 중인 일정 수
- 이번 달 수확(완료) 수
- 시들고 있는 봉우리 수(주의 알림)
- 포기(썩음) 수

**3.1.2 식물 관리 보드**
- 사용자가 가진 모든 식물(분야)의 미니 카드 그리드.
- 각 카드: 식물 외형 썸네일, 분야 이름, 매달려 있는 봉우리 수, 가장 임박한 마감.
- 카드 클릭 시 해당 식물 페이지로 이동.

**3.1.3 캘린더 AI**
- 월/주 단위 캘린더.
- 봉우리들 중 마감일이 설정된 항목이 시각적으로 표시됨.
- AI가 캘린더 옆에 텍스트로 요약: "이번 주에는 학업 식물의 봉우리 2개가 열매 단계에 있습니다.".
- 캘린더 항목 클릭 시 해당 봉우리 상세로 이동.

**3.1.4 시들고 있는 식물 섹션**
- 마지막 진행으로부터 N일 이상 정체된 봉우리/식물을 별도 강조.
- 각 항목에 "AI에게 상담받기" 진입점 제공.
- 사용자가 직접 "포기" 또는 "다시 시작" 액션을 발화로 처리.

**3.1.5 오늘의 정원 메시지**
- 접속 시 AI가 그날의 정원 상태를 한 문단으로 브리핑.
- 예: "오늘은 연애 식물의 봉우리 하나가 꽃을 피우기 직전입니다. 학업 식물의 한 봉우리는 5일째 정체되어 있습니다."

---

### 3.2 식물(Plants)

식물 화면은 두 단계로 나뉜다: **식물 목록 → 식물 상세**.

**3.2.1 식물 목록**
- 분야별 식물들을 시각적으로 큰 일러스트로 배치.
- 정원 풍경처럼 보이도록 배치. 각 식물의 건강도(진행도, 시듦 여부)에 따라 외형이 달라진다.
- 정렬: 활동량 순 / 생성 순 / 분야 이름 순.
- 빈 정원에서는 AI가 "어떤 분야의 식물을 먼저 키우고 싶으신가요?"라고 제안.

**3.2.2 식물 상세**
- 식물 하나에 매달린 모든 봉우리를 시각적으로 표시.
- 각 봉우리는 상태에 따라 모양이 다름(씨앗/봉우리/꽃/열매/시듦/썩음).
- 봉우리 클릭 시: 제목, 설명, 생성일, 마감일, 진행률, 그동안의 AI 대화 로그, 상태 변경 이력.
- 식물 자체 정보: 분야명, 정의(사용자가 처음 만들 때 LLM이 정리한 설명), 색감/종, 누적 수확 수, 누적 썩음 수.
- 액션은 모두 대화로: "이 봉우리 꽃 피웠어", "이건 포기할래", "마감일 다음 주 금요일로 바꿔줘".

**3.2.3 봉우리 상태 전이 규칙(요약)**
- Seed → Bud: 생성 직후 자동.
- Bud → Flower: 사용자가 "본격적으로 진행 중"이라고 발화하거나, 진행률이 일정 이상.
- Flower → Fruit: 마무리 단계 발화 또는 진행률 임계치.
- Fruit → Harvest: "끝났어", "해결됐어" 발화.
- Any → Wilting: 일정 기간 변화 없음(시간 기반 자동).
- Any → Rot: 사용자의 명시적 포기 발화.
- Rot은 일정 시간 후 사라짐(데이터는 보관, 시각적으로만 제거).

---

### 3.3 설정(Settings)

**3.3.1 계정**
- 로그인/로그아웃, 비밀번호 변경, 닉네임.
- 계정 데이터 내보내기(폴더 zip), 가져오기.
- 계정 삭제(로컬 폴더 제거).

**3.3.2 AI 설정**
- LLM 모델 선택(가능한 경우).
- API 키는 서버 환경변수로 관리하므로 사용자 입력창을 제공하지 않는다.
- 톤(따뜻한 상담사 / 담백한 비서 / 친구) 선택.
- AI가 사용자를 부르는 호칭.

**3.3.3 정원 규칙**
- 시듦 임계 일수(예: 7일).
- 썩음 후 사라지기까지의 일수.
- 자동 상태 전이 사용 여부.
- 마감일 임박 알림 기준일.

**3.3.4 시각/사운드**
- 배경 테마(계절 정원, 야간 정원 등).
- 효과음 on/off, BGM on/off, 볼륨.
- 식물 애니메이션 강도.

**3.3.5 데이터**
- 로컬 데이터 폴더 위치 보기.
- 백업/복구.
- 대화 로그 삭제(식물/봉우리는 유지).

**3.3.6 정보**
- 버전, 라이선스, 도움말.

## 4. AI 대화 흐름

대화창은 어느 페이지에서나 열 수 있고, 현재 페이지의 컨텍스트(어떤 식물/봉우리를 보고 있는지)를 자동으로 포함한다.

### 4.1 새로운 고민/일정 입력
1. 사용자 발화: "요즘 진로 때문에 고민이야."
2. LLM이 분야 추정 → 기존 식물 중 매칭 시도.
3. 매칭 결과 응답:
   - 매칭됨: "이 고민은 '진로' 식물과 관련이 있어 보입니다. 이 식물에 새 꽃을 피울까요?"
   - 매칭 없음: "이 고민은 기존 식물과 잘 맞지 않습니다. '진로'라는 새 식물을 심을까요?"
4. 사용자 확인 → 봉우리 생성(`bud` 상태).
5. 후속 질문으로 마감일/중요도/세부 내용 보강.

### 4.2 진행 보고
1. 사용자 발화: "어제 자소서 초안 다 썼어."
2. LLM이 어떤 봉우리에 대한 진행인지 추정 → 확인 질문.
3. 확정 시 봉우리 상태/진행률 업데이트, 필요한 경우 단계 전이(꽃→열매 등).

### 4.3 완료/포기
- 완료: "이거 다 끝냈어." → Harvest, 통계 +1, 식물 상세에 수확 로그 남김.
- 포기: "이건 그만할래." → Rot. AI가 가볍게 회고 질문("어떤 점이 어려웠나요?") 후 종료.

### 4.4 회고/통계 질의
- "이번 달 내가 뭐 끝냈어?" → 통계 조회 응답.
- "가장 오래 정체된 봉우리는?" → 데이터 기반 응답.
- "나 요즘 어때?" → 진행 중/시듦/완료의 분포 기반 정성적 답변.

### 4.5 AI의 자발적 발화(트리거 기반)
- 접속 시 오늘의 정원 메시지.
- 시듦 임계 도달 시 알림.
- 마감 임박 시 알림.
- 장기간 손대지 않은 식물에 대한 부드러운 환기.

## 5. 데이터 모델(논리적 스케치)

> 실제 파일 구조가 아닌, 개념 모델.

- **User**
  - id, nickname, password_hash, created_at
- **GardenState**
  - last_opened_at, summary_cache(진행 중/완료/시듦/썩음 카운트)
- **Plant**
  - id, name(분야명), description, species(외형), color, created_at, stats(harvested_count, rot_count)
- **Bud**
  - id, plant_id, title, detail, type(고민/일정), status, progress, created_at, last_progress_at, deadline(optional), history[]
- **ConversationLog**
  - id, scope(global/plant/bud), ref_id, messages[]

## 6. 상태 자동 갱신 규칙

프로그램이 켜질 때, 그리고 주기적으로 다음을 점검한다.

1. 모든 활성 봉우리의 `last_progress_at`을 확인.
2. 임계 일수를 초과한 봉우리는 Wilting으로 전이.
3. Wilting 상태가 추가 임계를 넘으면 AI가 "포기/재시작" 질문을 제안 큐에 추가(자동 포기는 하지 않음).
4. 마감일이 가까운 봉우리는 알림 큐에 추가.
5. Rot 상태가 설정된 일수를 넘으면 시각적으로 사라짐 처리(데이터는 보관).
6. 활성 봉우리가 0인 식물은 "휴면" 표시.

## 7. 사용자 시나리오 예시

**시나리오 A — 새 고민**
1. 사용자: "요즘 돈 관리가 너무 어려워."
2. AI: "이건 '돈' 식물과 관련이 있어 보입니다. 새 꽃을 피울까요?"
3. 사용자: "응."
4. → '돈' 식물에 `bud` 봉우리 생성, 제목 "돈 관리 어려움", AI가 후속 질문으로 구체화.

**시나리오 B — 진행**
1. 사용자: "이번 주에 가계부 앱 깔고 3일 기록했어."
2. AI: "'돈 관리' 봉우리가 꽃으로 자랐어요."

**시나리오 C — 시듦/포기**
1. 7일간 진행 없음 → 봉우리가 Wilting.
2. AI: "'돈 관리' 봉우리가 시들고 있어요. 계속 키울까요, 포기할까요?"
3. 사용자: "포기할래."
4. → Rot. 며칠 후 시각적으로 사라짐.

**시나리오 D — 수확**
1. 사용자: "프로젝트 끝났어!"
2. AI: 어떤 봉우리인지 확인 후 Harvest 처리, 홈 통계의 "이번 달 수확"이 +1.

## 8. 현재 웹 구현 기준

- 신규 봉우리는 `bud` 상태로 시작한다. 과거 `seed` 상태는 제거됐고, 남아 있는 `seed`
  참조는 migration 미적용 환경을 위한 읽기 호환 또는 과거 asset 명칭일 수 있다.
- 수확은 진행률 100%인 봉우리만 가능하다.
- 봉우리는 `PATCH /api/v1/buds/{bud_id}/move`로 같은 사용자 소유의 다른 식물로 이동할 수
  있다. 일반 `PATCH /buds/{id}`에는 `plant_id`를 열지 않는다.
- 캘린더에는 `buds.deadline` 기반 식물 일정과 `calendar_events` 독립 일정이 함께 표시된다.
  독립 일정은 시작/종료 날짜, 선택 시간, 하루 종일 여부, 반복 규칙, 색상을 저장한다.
  하루 종일 일정은 시간 입력을 숨기고, 시간 지정 일정은 `HH:MM-HH:MM` 형태로 표시한다.
  독립 일정은 `olive`, `blue`, `yellow`, `red`, `pink`, `purple` 팔레트 중 하나를 저장한다.
- 앱 시간은 백엔드 `runtime_settings.rs.now()/today()`를 사용한다. 사용자 표시 날짜에
  `datetime.utcnow()`를 직접 적용하지 않는다. 프론트 사용자 표시 날짜는
  `frontend/lib/time.ts`의 KST formatter를 우선 사용한다.
- 대화 기록 Markdown은 `frontend/lib/markdown.tsx` 렌더러를 ChatPanel과 `/history`가
  공유한다.
- 관리자 권한의 실제 경계는 백엔드 `require_admin`이다. 프론트 가드는 보조 수단이다.

컨텍스트와 스크린샷을 읽어 현재 프론트 화면과 비교한다. 화면 단위 수정 후 관련 라우트를
Codex 인앱 브라우저에서 다시 확인한다.

### 9.1 공통 UI

- 앱 공통 색상은 `frontend/app/globals.css` 토큰을 기준으로 한다.
- 테마 설정은 light, dark, system 모드만 제공한다. 별도 강조색 선택 기능과 `data-accent`
  DOM 속성은 다시 추가하지 않는다.
- 사이드바 기준 프레임은 `31:3`이며, 프론트 구현은
  `frontend/components/layout/Sidebar.tsx`다.
- 사이드바 아이콘은 Figma와 동일한 공식 라이브러리 SVG path를 직접 사용한다.
  Figma MCP 임시 asset URL은 만료되므로 프론트 코드에 직접 넣지 않는다.
- AI 패널 토글은 사이드바의 `AI 정원사` 버튼 하나만 제공한다. 공통 앱 레이아웃의 우측
  상단 floating FAB는 중복이므로 다시 추가하지 않는다.

### 9.2 캘린더

- 달력 아래에 선택 날짜 일정을 다시 길게 반복 표시하지 않는다.
- 일정 추가 진입점은 오른쪽 열 하단의 버튼 하나만 유지하고 헤더 우측에는 두지 않는다.
- 오른쪽 열은 월간 달력 카드 높이에 맞춘다. 일정이 많으면 `선택 날짜 일정` 목록 내부
  스크롤로 확인한다.
- `선택 날짜 일정` 카드와 오른쪽 열은 `overflow: hidden`을 유지하고 목록 `<ul>`은
  `flex: 1`, `min-height: 0`, `overflow-y: auto`를 사용한다.
- 캘린더 레이아웃 기준은 `frontend/app/globals.css`의 `.app-page-calendar`와
  `.calendar-layout`이다. 큰 화면에서 달력 칸이 옆으로만 과도하게 늘어나지 않게
  페이지와 왼쪽 달력 컬럼의 최대 폭을 제한한다.

### 9.3 대화 기록

- `/history` 왼쪽 목록은 스코프 계층을 시각적으로 유지한다.
- 전체 대화는 message-circle, 캘린더는 calendar, 식물은 sprout, 일정 봉우리는 calendar,
  고민 봉우리는 stage dot 아이콘을 이름 앞에 표시한다.
- 식물 아래 봉우리는 들여쓰기 가이드로 연결하고, 식물 행의 보조 문구는 최근 메시지
  미리보기보다 하위 봉우리 개수를 우선 표시한다.

### 9.4 랜딩 preview

- 랜딩 페이지는 `header`, 단일 `main`, `footer` 랜드마크 구조를 유지한다.
- 하단 `지금 바로 정원을 시작하세요` CTA에는 별도 로고를 두지 않는다.
- 상단 `AI 정원사` 모델 배지는 `GET /api/v1/public/runtime`의
  `llm_default_model_label`을 표시하고, 관리자 기본 모델 변경을 따라가야 한다.
- `#preview`의 `나의 정원` 예시는 실제 `/plants` 픽셀 규칙을 따른다. 오래된
  `plant.png + 6개 슬롯` 합성이나 `sky.png`, `grass.png` 배경으로 되돌리지 않는다.
- 식물 픽셀과 정보 카드는 `frontend/components/plants/GardenPlantVisual.tsx`의
  `GardenPlantVisual` 합성 컴포넌트를 `/plants`와 랜딩이 함께 사용한다.

### 9.5 정원 화면

- `/plants` 정원 보기는 Figma `03 App Screens`의 `Plant / View / Garden` 프레임과
  `05 Plant Pixel Assets` 가이드를 따른다.
- 좌측 상단 제목 HUD 아래에는 `정원`, `리스트` 전환 HUD만 둔다. 별도의 `N개 식물`,
  `시듦 N` 요약 HUD와 우측 상단 전환 HUD를 다시 추가하지 않는다.
- 우측 하단에는 `50%`, `75%`, `100%`, `125%`, `150%`, `175%`, `200%` 배율을 선택하는
  확대, 축소 HUD를 둔다. 트랙패드 pinch의 `ctrlKey` wheel 이벤트도 배율 변경으로 처리한다.
- 정원 페이지는 SSR과 첫 hydration 렌더에서 항상 정원 스켈레톤을 표시한다.
  `useSyncExternalStore`로 hydration 완료를 확인한 뒤 Supabase access token이 있을 때만
  plants, buds query를 활성화한다.
- 식물이 없는 정원 모드도 풀스크린 잔디 보드를 렌더링한다. 첫 번째 자리에는
  `첫 식물 심기` 버튼을 두고 AI 채팅을 연다.
- 정원 식물은 화분을 맨 아래에 한 번만 렌더링하고, 사라지지 않은 봉우리마다
  `no-pot extension` 성장 레이어를 하나씩 위로 쌓는다. 줄기 하나에 봉우리 하나가
  대응한다.
- 식물 정보 카드에는 대표 상태 pill을 표시하지 않는다. 식물명, 봉우리 수,
  `상세`·`상담` 액션만 유지한다.
- 식물 상세 화면에서는 이름과 설명을 직접 수정할 수 있다. 저장은 기존
  `PATCH /plants/{id}` API를 사용하고, 식물 목록/상세/브리핑/캘린더 캐시를 무효화한다.
- 정원 리스트 카드의 가로 바는 상태 개수 분포가 아니라 식물의 전체 진행률을 표시한다.
  수확되었거나 포기된 봉우리는 평균에서 제외하고, 나머지는 현재 progress 값을 그대로
  평균에 넣는다. 100%라도 아직 수확되지 않은 봉우리는 포함한다.
  `N% · M개 봉우리 · K개 진행 중` 텍스트와 바의 채움 비율이 일치해야 한다.
- 상태별 픽셀 표현은 `frontend/components/plants/GardenPlantVisual.tsx`의 `GrowthLayer`가
  담당한다.
- `/plants` 정원 화면에서 봉우리 레이어를 클릭하거나 키보드로 선택하면 페이지 이동 없이
  같은 정원 화면 위에 `BudDetailDrawer`를 연다.
- 봉우리 상세 drawer는 정원 화면과 식물 상세 화면 모두에서 제목과 detail을 직접 수정할
  수 있다. 저장은 `PATCH /buds/{id}` API를 사용하고, 봉우리/식물별 봉우리/캘린더/브리핑
  캐시를 무효화한다.
- `harvested`는 별도 열매나 수확 마커를 남기지 않고 줄기와 잎만 있는 새싹 형태로 표시한다.
  봉우리가 하나도 없는 식물은 대체 새싹 레이어를 만들지 않고 화분만 표시한다.
- 수확된 봉우리는 정원 왼쪽의 `GardenHarvestBasket` 바구니에 모은다. 바구니는 손잡이
  없는 낮은 수확 바구니 형태를 유지하고, 맨 아래 별도 진한 갈색 base 줄은 두지 않는다.
  `BASKET_VISUAL_H`는 실제 바구니 픽셀 하단과 맞춰 정원 기준선 위에 떠 보이지 않게 한다.
- 각 봉우리 성장 레이어의 방향은 식물 ID와 무관하게 해당 봉우리 ID 해시만으로 안정적으로
  섞는다. 같은 방향은 최대 3개까지만 연속되게 보정한다.
- `bud` 줄기도 다른 활성 상태와 같은 연한 초록색을 사용한다.
- 봉우리 단위 좌우반전은 줄기 중심축 기준이므로 `GrowthLayer`의 반전 `transformOrigin`은
  `90px 0`을 유지한다.
- 봉우리 hover는 성장 레이어 오른쪽 고정 위치에서 이름 툴팁의 투명도만 바꾼다.
  hover 중에도 성장 레이어 z-index와 툴팁 위치를 바꾸지 않는다.
- 정원 식물은 `created_at` 오름차순으로 왼쪽부터 배치한다. 새 식물은 항상 기존 식물
  오른쪽, `새 식물 자리` 버튼 바로 앞에 추가된다.
- 일반 식물 기준선은 `696px`, 기본 최소 높이는 `1160px`, 전경 잔디는 하단 `120px` 띠를
  기준으로 한다. 봉우리가 길어지면 `skyExtension`만큼 하늘을 위쪽에 추가하고, 잔디 경계,
  바닥 그림자, 화분 기준선도 함께 이동한다.
