# 도메인 서비스

Router와 AI 스킬은 서비스 계층을 통해 도메인 로직을 공유한다. DB 접근은 repository에
둔다.

| 서비스 | 책임 |
| --- | --- |
| `UserService` | 프로필 수정, 계정 삭제, 사용자 API 키 암호화 |
| `PlantService` | 식물 생성, 조회, 수정, archive 또는 삭제, 유사 식물 검색 |
| `BudService` | 봉우리 CRUD, 진행률, 상태 전이, 마감일, 수확, 포기 |
| `GardenStateService` | 통계 요약과 브리핑 |
| `CalendarService` | 독립 일정 CRUD |
| `ConversationService` | 스코프별 기록, 검색, 삭제 |
| `TransitionService` | 시듦, 썩음, 마감 임박 자동 스캔 |
| `BackupService` | 관리자 전체 ZIP 백업과 비파괴 복원 |

## 계정 삭제

`UserService.delete_account()`는 봉우리, 식물, 대화, 정원 상태, 알림, AI 로그 파일,
프로필을 삭제하고 Supabase Auth 관리자 API로 인증 사용자 삭제도 시도한다.

## 규칙

- 사용자 데이터 메서드는 `user_id`를 전달한다.
- `BudService.update_status(..., "harvested")`는 진행률 `100%` 미만 수확을
  거부한다. AI 스킬과 향후 호출자는 이 공통 도메인 규칙을 우회하지 않는다.
- 직접 PostgreSQL 연결과 SQLAlchemy session을 추가하지 않는다.
- `calendar_events` repository만 현재 `exec_admin_query` RPC 예외를 사용한다.

## 주요 메서드

```text
PlantService.create / get / list / update / delete / find_matches
BudService.create / get / list / update_status / update_progress
BudService.set_deadline / delete / abandon / harvest / mark_wilting
GardenStateService.refresh_summary / compute_stats / build_briefing
ConversationService.append / get_history / list_conversations / search
TransitionService.scan_all / scan_user
BackupService.create_backup / list_backups / restore_backup
```

스킬 구현은 가능한 한 서비스 메서드를 호출한다. 사용자별 필터와 도메인 규칙을
라우터, 스킬, 스케줄러에 중복 구현하지 않는다.
