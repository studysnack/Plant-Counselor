# 도메인 서비스

> Service 레이어는 비즈니스 규칙의 집중지. 모든 Skill과 라우터가 호출한다.

관련 문서: [[아키텍처_개요]], [[Web/03_LLM/Skill_개요]], [[DB_스키마]]

---

## 공통 규약

- 모든 서비스 메서드는 첫 인자로 `user_id` 또는 `current_user`를 받는다.
- DB 트랜잭션은 서비스 레이어가 관리한다.
- 비즈니스 검증(예: 마감일 형식, 상태 전이 적법성)도 서비스 레이어에서 한다.
- 검증 실패는 도메인 예외(`DomainError(code, message)`) 발생 → 라우터/Skill이 표준 응답 형식으로 매핑.

## AI 레이어와의 관계

[[Web/05_백엔드/AI_연동]]의 Skill 구현 클래스는 위 서비스를 호출한다.

- `CreatePlantSkill.run` → `PlantService.create`
- `UpdateBudStatusSkill.run` → `BudService.update_status`
- `GetStatisticsSkill.run` → `GardenStateService.compute_stats`
- `GetGardenBriefingSkill.run` → `GardenStateService.build_briefing` + `BudService.list`

이렇게 한 군데(Service)에 비즈니스 규칙을 모아 Skill·라우터·스케줄러가 동일한 규칙을 공유한다.
