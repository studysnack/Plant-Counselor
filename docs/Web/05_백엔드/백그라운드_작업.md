# 백그라운드 작업

> 최종 점검: 2026-06-02

`backend/app/scheduler/jobs.py`가 FastAPI lifespan에서 APScheduler를 시작한다.

## 잡

| 이름 | 기본 주기 | 동작 |
| --- | --- | --- |
| `transition_scan` | 10분 | 모든 프로필의 정원 규칙을 읽고 `TransitionService.scan_all()` 실행 |

한 번의 스캔에서 다음을 처리한다.

1. 오래 활동이 없는 활성 봉우리를 `wilting`으로 변경한다.
2. 오래 시든 봉우리를 `rot`으로 변경하고 사라진 시각을 기록한다.
3. 마감 임박 봉우리에 중복 없는 알림을 생성한다.

## 시간

`runtime_settings.py`의 `rs.now()`와 `rs.today()`를 사용한다. 기본 앱 타임존은
UTC+9이며 관리자 타임 트래블을 반영한다.

관리자 화면은 `POST /api/v1/admin/controller/scheduler/trigger`로 수동 스캔을
실행할 수 있다.

Render 무료 인스턴스가 sleep 상태이면 in-process 스케줄러도 멈춘다.

현재 별도 Celery worker, Redis, 분산 lock은 없다. FastAPI 인스턴스를 여러 개
운영하면 스캔 중복 실행 가능성을 검토해야 한다.
