# 백그라운드 작업

> 시간 기반 자동 상태 전이와 알림 큐 적재.

관련 문서: [[Web/02_기능/상태_자동전이]], [[Web/02_기능/알림]], [[도메인_서비스]]

---

## 실행 모델

### 개발(단일 프로세스)
- **APScheduler** 인메모리 + FastAPI 라이프사이클에 붙는다.
- 주기: 기본 10분.

### 운영(분리 워커)
- **Celery + Redis** 권장.
- 워커 컨테이너가 별도. FastAPI 인스턴스를 여러 개 띄워도 작업은 한 번만 실행되도록 분산락 또는 단일 워커 가정.

---

## 잡 목록

| 잡 이름 | 주기 | 동작 |
|---|---|---|
| `transition_scan` | 10분 | 모든 사용자에 대해 [[TransitionService]].`scan_user` 실행 |
| `deadline_scan` | 30분 | 마감 임박 봉우리에 대해 알림 큐 적재 |
| `briefing_refresh` | 매일 06:00 (사용자 타임존) | 오늘의 정원 메시지 캐시 무효화. 첫 접속 시 재생성. |
| `snapshot_create` | 매일 03:00 | 사용자별 자동 스냅샷 생성 |
| `purge_disappeared` | 매일 04:00 | rot 만료 봉우리 시각적 사라짐 처리 |

> 알림은 큐에만 적재. 푸시 전송은 별도(웹푸시 도입 시).

---

## 사용자 타임존

- 사용자별 타임존(`User.timezone`)이 있을 경우 일/주/달 경계를 이 타임존 기준으로 계산.
- 없으면 UTC.

---

## 안전 가드

- 한 사용자에 대해 동일 잡이 동시에 두 번 돌지 않도록 사용자 + 잡 이름 키로 락.
- 잡 실패 시 로그 + 재시도(지수 백오프, 최대 3회). 회복 불가능 오류는 알림으로 표시.

---

## 모니터링

- 잡 실행 시각/길이/오류 카운트를 메트릭(prometheus 등)으로 노출.
- 운영용 엔드포인트 `POST /maintenance/scan`로 수동 트리거 가능.
