## 레이어와 의존 방향

```
Routers  →  Services  →  Repositories  →  DB
                ↓
            AI Layer (Skills) → Services (재진입)
                ↓
            LogRecorder → logs/chat/*.json
```

- **위에서 아래로만 의존**. Repositories는 Routers를 모른다.
- Skill 구현은 Service 메서드만 호출. DB·ORM 직접 접근 금지.
- LLMClient는 외부 API 호출 캡슐화. 다른 레이어가 Gemini SDK를 직접 사용하지 않는다.

## 사용자 데이터 격리

- 모든 비즈니스 테이블은 `user_id` 외래키로 사용자 단위 격리.
- 모든 라우터 핸들러는 `deps.py`의 `get_current_user` 의존성으로 사용자 컨텍스트를 받는다.
- 서비스 메서드는 항상 `user_id`를 인자로 받아 다른 사용자 데이터 접근을 차단.

## 환경 변수

| 키 | 의미 |
|---|---|
| `DATABASE_URL` | SQLite 파일 또는 Postgres DSN |
| `JWT_SECRET` | 액세스 토큰 서명 키 |
| `JWT_ACCESS_TTL` | 액세스 토큰 만료(분, 기본 15) |
| `JWT_REFRESH_TTL` | 리프레시 만료(일, 기본 14) |
| `LLM_API_KEY` | Gemini API 키 |
| `LLM_MODEL` | 기본값 `gemini-2.5-flash` |
| `CORS_ALLOW_ORIGIN` | 프런트 도메인 |

## 보안 원칙

1. 모든 쓰기 엔드포인트는 인증 필수.
2. Skill 호출은 항상 현재 사용자 컨텍스트에 묶임.
3. `deps.py`의 Authorization 헤더는 `Header(None, ...)` + 없으면 명시적 401 반환 (422 방지).
4. CORS는 최소 도메인만 허용.

## 배포 시나리오

- **개발**: SQLite + uvicorn + `next dev` (pnpm)
- **운영**: PostgreSQL + uvicorn behind nginx + Next.js standalone/SSR
- **백그라운드**: 개발은 APScheduler in-process, 운영은 별도 워커 고려
