# 백엔드 아키텍처 개요

> 최종 점검: 2026-06-02

관련 문서: [[API_엔드포인트]], [[인증_세션]], [[DB_스키마]]

## 요청 흐름

```text
Browser
  -> FastAPI router
  -> service
  -> repository
  -> Supabase PostgREST HTTP
```

AI 채팅은 별도 흐름을 추가한다.

```text
POST /api/v1/chat/message
  -> ChatOrchestrator
  -> Gemini
  -> SkillRegistry
  -> skill
  -> service
  -> repository
```

## 계층 책임

| 계층 | 책임 |
| --- | --- |
| Router | 인증, HTTP 입출력, Pydantic 검증 |
| Service | 도메인 로직과 여러 repository 조합 |
| Repository | Supabase CRUD, 사용자별 `user_id` 격리 |
| AI | Gemini 호출, ReAct 루프, 스킬 권한, 로그 |

백엔드는 SQLAlchemy session, psycopg2 직접 연결, SQLite를 사용하지 않는다.

## 주요 파일

```text
backend/app/
├── main.py                    # FastAPI와 외부 CORS 래퍼
├── config.py                  # .env 설정
├── deps.py                    # Supabase JWT 검증, require_user, require_admin
├── db/supa.py                 # Supabase HTTP 클라이언트
├── routers/                   # 사용자 API와 관리자 API
├── services/                  # 도메인 로직
├── repositories/              # PostgREST 접근
├── schemas/                   # Pydantic 타입
├── ai/                        # Gemini ReAct와 20개 스킬
└── scheduler/jobs.py          # APScheduler
```

## DB 접근 규칙

- 일반 CRUD는 repository에서 `db.table("...")`을 사용한다.
- 사용자 데이터 쿼리는 필요한 경우 `user_id` 필터를 반드시 적용한다.
- `calendar_events`는 PostgREST 스키마 캐시 문제 때문에 현재
  `exec_admin_query` RPC를 사용한다.
- 사용자 입력을 SQL identifier 위치에 직접 넣지 않는다.

## CORS

`main.py`는 FastAPI 인스턴스를 만든 뒤 최종 ASGI 앱을 `CORSMiddleware`로 감싼다.
처리되지 않은 500 응답에도 CORS 헤더를 유지해 브라우저가 실제 오류를 CORS 실패로
가리지 않게 하기 위함이다.

`CORS_ALLOW_ORIGIN`에는 쉼표로 구분한 정확한 `http://` 또는 `https://` origin만
입력한다. wildcard, `null`, 빈 설정, path, query, fragment는 허용하지 않는다.

## 배포

- 로컬 백엔드: Poetry in-project `.venv`
- Render 백엔드: `requirements.txt` 기반 설치, `uvicorn app.main:app`
- Vercel 프론트: `frontend/`를 루트 디렉터리로 지정
- Supabase: PostgreSQL, Auth, PostgREST

## 환경 변수

| 변수 | 역할 |
| --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_JWT_SECRET` | HS256 fallback 검증용 legacy secret |
| `SUPABASE_SERVICE_ROLE_KEY` | 백엔드 PostgREST 접근 |
| `LLM_API_KEY` | 사용자별 키가 없을 때 Gemini fallback |
| `KEY_ENCRYPTION_SECRET` | 사용자별 Gemini 키 암호화 |
| `CORS_ALLOW_ORIGIN` | 허용할 정확한 브라우저 origin 목록 |

`DATABASE_URL`은 과거 호환 설정으로 남아 있지만 일반 CRUD에는 사용하지 않는다.

## 보안 원칙

1. 보호 API에 `require_user()` 또는 `require_admin()`을 적용한다.
2. repository 쿼리에 사용자별 `user_id` 필터를 유지한다.
3. service role key와 암호화 secret을 프론트에 노출하지 않는다.
4. 관리자 SQL 실행기와 `exec_admin_query` RPC 노출 범위를 넓히지 않는다.
5. credentials를 허용하는 CORS 설정에 wildcard origin을 사용하지 않는다.
