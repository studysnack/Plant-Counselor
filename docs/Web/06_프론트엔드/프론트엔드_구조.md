# 프론트엔드 구조

> 최종 점검: 2026-06-04

관련 문서: [[상태관리]], [[API_클라이언트]], [[채팅_스트리밍]]

## 기술

- Next.js 16.2.6 App Router
- React 19.2.4
- TypeScript
- Tailwind CSS v4와 `app/globals.css` 토큰
- TanStack Query v5
- Zustand

## 라우트

| 경로 | 역할 |
| --- | --- |
| `/` | 로그인 전 랜딩 |
| `/login` | Google OAuth 로그인 |
| `/home` | 요약 대시보드 |
| `/plants` | 픽셀아트 정원과 식물 리스트 |
| `/plants/[id]` | 식물 상세 |
| `/calendar` | 월간 캘린더와 독립 일정 |
| `/history` | 스코프별 대화 기록 |
| `/settings` | 계정, AI, 정원 규칙, 테마, 정보 |
| `/admin/*` | 관리자 패널 |

## 인증

Supabase 세션은 localStorage 기반이다. `frontend/proxy.ts`는 인증 redirect나 API
proxy를 하지 않고 pass-through만 수행한다. 앱 레이아웃과 관리자 레이아웃의
클라이언트 가드가 페이지 진입을 보조하고, 실제 데이터 권한은 백엔드가 검사한다.

## 상태

| 상태 | 위치 |
| --- | --- |
| 서버 데이터 | TanStack Query |
| 인증 | `lib/store/authStore.ts` |
| 채팅 | `lib/store/chatStore.ts` |

테마는 light, dark, system만 제공한다. `data-accent`는 제거됐고 초기화 시 이전
로컬 저장 흔적도 DOM에서 제거한다.

## 픽셀 정원

`components/plants/GardenPlantVisual.tsx`가 실제 `/plants` 정원과 랜딩 `#preview`
예시의 픽셀 식물, 화분, 정보 카드를 함께 렌더링한다. 랜딩에 별도 모사 구현을 만들지
않는다.

봉우리 하나당 `64px` 성장 레이어를 위로 추가한다. 식물이 길어져도 화분과 땅 기준선은
고정하고 하늘 영역이 늘어난다. 봉우리가 하나도 없는 식물은 성장 레이어 없이 화분만
표시한다. 상태별 조각은 Figma `05 Plant Pixel Assets`의 no-pot extension 좌표를
따른다. `bud` 줄기도 다른 활성 상태와 같은 연한 초록색을 사용한다. 성장 레이어
방향은 식물 ID와 무관하게 각 봉우리 ID 해시만으로 안정적으로 섞고, 아래쪽 레이어가
앞에 그려지도록 z-index를 역순으로 쌓는다. 같은 방향은 최대 3개까지만 연속되게
보정하며, hover 툴팁은 식물 오른쪽 고정 위치에서 투명도만 바꾼다.

## 반응형 레이아웃

사용자용 주요 화면은 `app/globals.css`의 전역 레이아웃 클래스를 우선 사용한다.

```text
.app-main
.app-page / .app-page-narrow / .app-page-wide
.responsive-grid-2 / .responsive-grid-3 / .responsive-grid-4
.responsive-card-grid
.calendar-layout
.calendar-summary-grid
.settings-layout
.history-shell
.history-layout
.chat-panel
```

`/home`, `/plants` 리스트, `/plants/[id]`, `/calendar`, `/history`, `/settings`는 고정
`maxWidth`와 고정 컬럼 수를 각 페이지에 반복하지 않고 이 클래스들로 처리한다. 큰
화면에서는 `app-page-wide`가 더 넓은 컨텐츠 폭을 쓰고, 좁은 화면에서는 캘린더,
설정, 히스토리의 2단 레이아웃이 한 컬럼으로 접힌다. 채팅 패널은 데스크톱에서만
본문을 밀며, 좁은 화면에서는 오버레이처럼 떠서 본문 폭을 더 줄이지 않는다.

랜딩과 로그인은 `landing-container`, `login-shell`, `login-brand-panel` 규칙을
사용한다. 로그인 brand panel은 좁은 화면에서 숨기고 로그인 폼은 전체 폭 중앙 카드가
된다. 관리자 화면은 `admin-shell`, `admin-sidebar`, `admin-main`, `admin-page`,
`admin-grid-2`, `admin-table-card`를 사용한다. 좁은 화면에서 관리자 sidebar는 상단
sticky 영역으로 바뀌며, 넓은 테이블은 페이지 전체 overflow 대신 카드 내부 가로
스크롤로 확인한다.

## Next.js 16 주의

`frontend/` 아래 파일을 수정할 때는 `frontend/AGENTS.md`를 먼저 읽는다. 특히
`middleware.ts` 대신 `proxy.ts`를 사용하는 Next.js 16 규칙을 확인한다.

## CSS 토큰

공통 색상은 `app/globals.css`의 CSS 변수를 사용한다. 테마를 수정할 때 개별
컴포넌트에 임의 색을 반복해서 넣기 전에 토큰으로 표현할 수 있는지 확인한다.
