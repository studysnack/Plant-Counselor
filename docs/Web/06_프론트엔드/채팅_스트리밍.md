# 채팅 스트리밍

> `POST /chat/message`의 SSE 응답 프로토콜과 프론트엔드 처리.

관련 문서: [[Web/01_페이지/공통_AI대화창]], [[Web/03_LLM/LLM_흐름]], [[API_엔드포인트]], [[Web/05_백엔드/AI_연동]]

---

## 응답 형식

- Content-Type: `text/event-stream`
- 이벤트는 `event: <type>\ndata: <json>\n\n` 페어로 송신
- `event: done`까지 클라이언트는 스트림을 계속 읽는다

---

## 이벤트 종류

| event | data 예시 | 의미 |
|---|---|---|
| `token` | `"오늘은 "` | 부분 토큰 (raw 문자열) |
| `tool_call` | `{"name": "create_plant", "args": {...}}` | LLM이 Skill 호출 시작 |
| `tool_result` | `{"name": "create_plant", "ok": true, ...}` | Skill 실행 완료 |
| `error` | `{"code": "...", "message": "..."}` | 처리 도중 오류 |
| `done` | `""` | 응답 종료 |

`confirmation_required` 이벤트는 **존재하지 않는다** — 동의 확인은 LLM이 대화 텍스트로 처리.

---

## 프론트엔드 구현 (`lib/api/client.ts` → `streamChat`)

- `EventSource`는 POST 미지원 → `fetch` + `ReadableStream`으로 수동 파싱.
- 콜백 구조:
  ```typescript
  streamChat(body, {
    onToken: (chunk) => { /* 텍스트 누적 렌더 */ },
    onToolResult: (name) => { /* dirtySkills에 추가 */ },
    onDone: () => { /* Skill 실행 시 관련 쿼리 캐시 무효화 */ },
    onError: (code, message) => { /* 에러 메시지 렌더 */ },
  })
  ```

## TanStack Query 캐시 무효화

`ChatPanel.tsx`에서 Skill 실행이 완료되면 관련 쿼리를 자동 무효화한다:

```typescript
const SKILL_INVALIDATIONS = {
  create_plant:        [["plants"], ["stats"]],
  delete_plant:        [["plants"], ["buds"], ["stats"]],
  create_bud:          [["buds"], ["plants"], ["stats"]],
  update_bud_status:   [["buds"], ["plants"], ["stats"]],
  update_bud_progress: [["buds"]],
  harvest_bud:         [["buds"], ["plants"], ["stats"]],
  abandon_bud:         [["buds"], ["plants"], ["stats"]],
  set_deadline:        [["buds"]],
}
```

`onDone` 시 `dirtySkills`에 모인 이름으로 해당 쿼리키를 `invalidateQueries`.

---

## 인증

- 일반 보호 엔드포인트와 동일하게 `Authorization: Bearer <access_token>` 헤더 필요.
- 스트림 시작 전 401 수신 시 클라이언트가 자동 갱신(refresh) 후 재요청.

---

## 요청 바디

```typescript
{
  text: string           // 사용자 발화
  scope: "global" | "plant" | "bud"
  scope_id?: string      // 식물/봉우리 ID (scope != global)
  current_screen: string // 현재 화면 힌트 ("웹", "홈" 등)
}
```
