# 관리자 데이터 백업과 복원

현재 백업은 일반 사용자 설정 기능이 아니라 관리자 기능이다.

## ZIP 구조

`backend/app/services/backup_service.py`가 `backend/backups/`에 ZIP을 만든다.

```text
backup_YYYYMMDD_HHMMSS.zip
├── meta.json
└── data.json
```

- `meta.json`: 버전, 실제 UTC 생성 시각, 테이블별 행 수
- `data.json`: 전체 테이블 데이터

## 동작

- 생성: `POST /api/v1/admin/backup`
- 목록: `GET /api/v1/admin/backups`
- 다운로드: `GET /api/v1/admin/backups/{filename}/download`
- 복원: `POST /api/v1/admin/backups/{filename}/restore`
- 삭제: `DELETE /api/v1/admin/backups/{filename}`

복원은 기존 PK를 덮어쓰지 않는다. 이미 존재하는 행은 건너뛰고 새 행만 FK 의존
순서로 추가한다.

`calendar_events`는 PostgREST 스키마 캐시 문제 때문에 `exec_admin_query` RPC로
덤프하고 복원한다.

Render의 휘발성 디스크에서는 재배포나 재시작 시 ZIP이 사라질 수 있다.
