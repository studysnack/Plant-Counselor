## 토큰 모델

- **Access Token (JWT)**: 짧은 만료(기본 15분). 응답 바디로 전달, 프런트가 메모리(Zustand) 보관.
- **Refresh Token**: 긴 만료(기본 14일). `HttpOnly; Secure; SameSite=Lax` 쿠키.

> 액세스 토큰을 localStorage에 저장하지 않는다(XSS 위험).

---

## 페이로드

```
{
  "sub": "<user_id>",
  "email": "...",
  "iat": ...,
  "exp": ...,
  "type": "access"   // or "refresh"
}
```

서명: HS256 (`JWT_SECRET`).

## 흐름

### 회원가입
1. `POST /auth/signup` → 검증 → 사용자 생성 → 빈 [[GardenState]] 초기화.
2. 자동 로그인은 하지 않음. 로그인 화면으로 안내.

### 로그인
1. `POST /auth/login` (email, password).
2. 서버: 비밀번호 해시 확인(argon2id) → access + refresh 발급.
3. 응답:
   ```
   { "ok": true, "data": { "access_token": "...", "user": {...} } }
   ```
   + `Set-Cookie: refresh=...; HttpOnly; Secure; Path=/; SameSite=Lax; Max-Age=...`

### 보호 엔드포인트 호출
- 헤더: `Authorization: Bearer <access_token>`.

### 액세스 만료 → 자동 갱신
1. 프런트 fetch 래퍼가 401 수신.
2. 즉시 `POST /auth/refresh` 호출(쿠키 자동 동봉).
3. 새 access를 Zustand에 저장한 뒤 원래 요청 재시도.

### 로그아웃
- `POST /auth/logout` → 리프레시 쿠키 만료 처리.

## 의존성 주입 (`app/deps.py`)

```python
# Authorization 헤더가 없으면 422가 아닌 401 반환
authorization: str | None = Header(None, alias="Authorization")
if not authorization:
    raise credentials_exception   # 401 HTTPException
```

- 이전 구현: `Header(...)` (필수) → 헤더 없으면 422 → 프런트 자동 갱신 불가.
- 현재 구현: `Header(None, ...)` (옵션) → 없으면 명시적 401 → 프런트가 refresh 흐름 실행.

## 인증 복원 (`(app)/layout.tsx`)

```typescript
async function restore() {
    const res = await refreshToken();
    if (!res.ok) { clearSession(); router.replace("/login"); return; }
    const token = (res.data as { access_token: string }).access_token;
    // 반드시 토큰 먼저 저장 — 이후 /me 호출에서 해당 토큰 사용
    useAuthStore.setState({ accessToken: token });
    const meRes = await apiGet<Record<string, unknown>>("/me");
    ...
}
```

- **중요**: `useAuthStore.setState`로 토큰을 먼저 저장한 뒤 `/me` 호출.
- 이전 버그: `/me` 호출 시 토큰 미저장 → 401 → 무한 refresh 루프.

## 비밀번호 정책

- 최소 길이 8자.
- argon2id 해시.
- 비번 변경 시 모든 refresh 토큰 무효화.

---

## CSRF

- 액세스 토큰은 Bearer 헤더(쿠키 아님) → CSRF 위험 낮음.
- 리프레시 쿠키는 `SameSite=Lax` + 갱신 엔드포인트만 사용.
